# 2026-11-20 本机 CE 负载测试

Ryzen 9 9950X3D，16 核 32 线程，Windows 11 build 26200。每个被测服务端进程固定在一颗逻辑 CPU，单个 Tokio 线程，Windows Job Object 提交内存上限 1 GiB。负载进程使用不同的逻辑 CPU，运行在同一宿主机。各配置读取外部 4.13.4 数据包。按 GameData 规则计算的内容 SHA-256 为 `26840b3da3181d0c25a7501738d93416c7b7762714f2888907a05a1a0e4f0e5b`，其中含 275 个选人目录条目。连接走回环 HTTPS 和双 GS TCP。初次登录和选人后的稳定期用于计算下表，后续自然结算、重新登录游戏连接、重新入局都计入时间。场景间共享宿主机内存、缓存和操作系统调度。

CPU 均值和最高约 60 秒滚动均值按被测服务端 PID 的 CPU 时间计算。RSS 为每五秒采样的工作集峰值。tick 从原计划时刻算到模拟广播入队完成，超时列使用整个区间内的累积计数。滚动 p99 是各房间最近最多 1024 步 p99 的采样最大值。每玩家下行含 GS 长度头，分母为配置的真人席位数，不计平台请求、TCP/IP 头或重传。

### 64 房间长测提前失败

以同一冻结镜像在逻辑核 14 启动 64 房间 / 640 真人长测。负载进程位于 25、27、28、29，独立于服务端及其 SMT 同胞 15。该构建使用固定 64 房间上限，当时尚无后续加入的资源准入采样。接满后的第 1336 秒，普通连接在客户端观察到结算前断开，运行失败。终止前最大单步 2822.4 ms，累计 15050 / 1713191 步超过 40 ms，采样 RSS 峰值 59.60 MiB。数据库中有 122 场已结算、63 场仍在进行；客户端已完成并重新入队 121 场。当时同机还有编译器和模拟器活动。

最后结算的是负载组 45 的第二局，数据库已写入全部十个玩家的结算事件，客户端没有写入离开赛后界面的事件。最慢单步则来自仍在运行的组 5 第三局。旧客户端错误未记录断开者的组号、席位和通道，服务端也未记录队列溢出的原因，因此这两局都不能直接认定为断开源。64 房间短测通过，长测失败，不宜用 64 作为持续容量。

### 64 房间短程诊断

在冻结模拟上添加连接关闭时的组号、房间、席位、通道、服务器连接代数、剩余队列空间及 tick 计数，另加已接纳状态和广播队列满计数。64 房间、每房 10 真人，90 秒分批登录后运行 240 秒，服务端逻辑核 16，负载逻辑核 17、19、21、23。服务端与负载端 SHA-256 前缀分别是 `d1a2feaef37368f9`、`daeb97b9df405106`。

64 个房间都通过准入，广播队列满计数为 0。客户端收到 23,912,019 帧，发出和收到的时钟回显均为 214,210，逐连接时钟序列异常为 0。所有 1280 条连接关闭记录集中在负载端按时退出的 0.24 秒内。仍有 35,728 / 303,214 个 tick 超过 40 ms，最高滚动 p99 689.9 ms，单步最高 749.4 ms。本次重现了高延迟，未重现长测中的提前断开。时钟序列可以检验这类帧；任意战斗事件的端到端完整性没有独立编码可供核对。

以上历史运行给服务端、负载端各分配一个 Tokio 工作线程。负载进程可以调度到多个指定核，但单线程解密、收发与排队的耗时可能影响读速。旧长测未采集负载进程 CPU，故不能把提前断开归因于服务端处理能力。后续工具按客户端 CPU 数设置工作线程并采集其 CPU 累积值，`--client-workers 1` 可复现旧设置。
