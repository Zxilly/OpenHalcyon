# 对局模拟规则

`World` 以 20 Hz 推进对局。单元测试使用 60 × 10 的验证地图。Solo Bots 使用录像标定的三路兵线、18 座炮塔、六座兵营和十个英雄出生点，ARAL 使用六个席位和该模式的结构坐标。英雄、塔、水晶和兵线均在同一个定步长循环中推进。摧毁敌方水晶即可取胜，ARAL 还支持队伍投降。[Solo 三路兵线](../../docs/solo-lane.md) · [ARAL](../../docs/aral.md)

模拟使用连续坐标、稳定实体 ID、固定遍历顺序和显式 seed。相同构建、数据、队伍和逐 tick 输入可以使用 `state_digest()` 对比，摘要包括待命中的弹道、冷却、路径、目标记忆和未公开的实体状态。联邦队列使用 `rules_digest()` 核对模拟源码和外部资料包。

## 战斗和成长

- 从外部 `units.json` 读取英雄、塔和各类小兵的基础数值、每级生命、能量、武器、护甲和护盾。验证地图按 45 秒首波、30 秒间隔发兵，每第四波用队长替换攻城兵。水晶按目标最大血量的 4% 发射攻击并附带减速。
- 普攻遵守射程、视野、出手前摇与恢复时间。远程英雄出手后弹道独立飞行，出手前走位会取消攻击。武器伤害按护甲、法术伤害按护盾计算。验证规则取基础攻击前摇 3 tick、恢复 17 tick、远程普攻弹速 18 单位/秒。完整客户端攻击动画和逐英雄攻速曲线仍需校准。
- Solo 开局 1 级、600 金币，开战 40 秒后每秒结算 3 金币和 0.6 经验。ARAL 开局 4 级、2,000 金币，开战 30 秒后每秒结算 15 金币和 1.8 经验。房间按模式选择升级曲线，重连时从权威账本恢复余额和累计收入。验证地图保留独立的经验曲线。[原始成长记录](../../docs/native-progression.md)
- 安装补充数据后，商店按模式检查 76 件普通商品的上架资格，另行处理开局赠送的治疗药剂和视野图腾。直接购买或用已有组件合成都按一次事务更新金币、实例和属性。ARAL 在余额或格位不足时发送拒绝回执。[装备效果与出售规则](../../docs/equipment-catalog.md) · [原版购买回执](../../docs/aral-shop.md)

## 技能

模拟接口包括 `Learn(A/B/C)` 和 `Cast {slot, target}`。按目标类型检查敌我、范围、视野、能量、等级和冷却。蓄力时走位、攻击、死亡会中断。释放时再次判定目标并扣能量。下表列出部分已实现的效果。已命名的 4.13 字段从外部 `official_rules.json` 载入；没有完整数表的前摇、耗能、伤害、距离和持续时间采用代码中的验证规则。`ability_raw.json` 仅保留提取证据。

| 英雄 | 技能 | 实现及数据边界 |
|---|---|---|
| Ringo | A / B / C | A 单体伤害、减速，B 加速并缩短普攻间隔，C 蓄力后追踪弹和三段后续伤害。4.13 确认 Ringo 武器成长，未重印这些技能的完整数值。 |
| Adagio | A / B | A 治疗友军并点燃附近敌人，自我施放还可减速。B 强化普攻并根据同一施法者的点燃状态计算额外伤害。 |
| Lyra | A / B | A 在目标处提供视野、治疗和伤害，可提前引爆。B 设置减速结界，获授权的对应天赋可让结界跟随施法者。 |
| SAW | B | 指定方向持续射击，使用公布的 DPS 和冷却。四个半秒脉冲可被走位打断。 |
| Idris | B | 飞轮去程和回程分别命中，回程追踪施法者，使用独立体力池。[数据与参数](idris.md) |
| Lorelai | A / B / C | 延时眩晕与持续伤害、水池移速、友军护盾与净化。施法会消耗施法者脚下的水池。[数据与参数](lorelai.md) |
| Karas | B | 朝指定点位移，沿途每个敌人至多受伤一次。地形、禁锢、眩晕和敌方结界可以截断位移。 |
| Shin | C | 指定方向连续三次伤害，每次基础伤害 200 源自 4.13。脉冲间隔和宽度来自验证规则。 |

九份实机通道档案里有 24 条学习请求、15 条点地施法和一条指定友方的施法。原版协议入口已接通四种英雄模板的已知学习槽，以及 Idris B 和 Lorelai A/B/C 的释放。其余表中技能可由模拟接口驱动，逐英雄原版输入映射仍需样本验证。[学习、施法与释放记录](../../docs/native-abilities.md)

## Bot 与导航

默认难度下英雄每五步分批决策。服务端将原版菜单的五档难度映射为每 16、10、5、3、2 个 tick 决策一次。Bot 考虑技能、撤退、已出手弹道预测的补刀窗口、目标切换成本和塔下友方兵线。避开视线遮挡，最近目击点最多记忆两秒。团队每秒确定己方兵线靠前的位置，英雄跟随推进。英雄在购买、选技和施法时与玩家共享规则。移动优先直接通行；遇到障碍时在固定十节点可视图上执行有界 A*，缓存折线路径。每 tick 至多新建六条路径，每次搜索最多扩展十个节点。

```powershell
cargo test -p halcyon-sim
cargo run --release -p halcyon-sim --example lane_bench -- ../vg/_ana/delivery
```

## 实体、系统和 Bot 的边界

每个房间独占一个可变的 `World`。定步长循环显式安排视野设备、持续效果、兵线、经济和实体行动的顺序。实体使用稳定的游戏 ID，同 tick 行动的优先顺序随 tick 和 seed 轮转。不同房间可并行推进。Bot 先按本队视野筛选敌人，再由英雄策略生成普通游戏命令。移动、攻击和施法沿用玩家的校验与结算入口，已接受的追击命令才会更新目标记忆。

Catherine 和 Yates 的四项专属效果在首次使用时共同分配，未启用的实体只占一个指针。Windows x86-64 构建中，实体内联尺寸由 936 降到 760 字节，战斗状态由 424 降到 248 字节，启用后另占 184 字节堆空间。固定队伍和种子的 Solo Bot 对局在第 35,445 个 tick 由队伍 1 获胜，改动前后的路径摘要和最终状态摘要相同。

双队视野实验使用两个 seed、两种地图，每组跑 2,400 tick，逐 tick 校验七种实现的有序输出。在最多 122 个存活实体的 Solo 房间，现有实现、按队拆分的向量、按队分组的 hecs、保留跨 tick 映射的 hecs 平均分别用时 27.90、28.63、30.11、41.65 µs。生产房间继续使用现有视野查询。新增需要跨实体批处理的系统时，可以按同样方法单独测量。整机容量另用多房间测试评估。[视野实验与复现命令](https://github.com/Zxilly/OpenHalcyon/tree/c6b1be0e556cc8054063129978071559da21ace1/tools/bench/ecs-visibility) · [多房间测量](../../tools/bench/aral-tick-latency.md)

Bevy ECS 另有两个可运行试验，分别测了视野广播和由 ECS 管理的持续技能。技能试验在正常对局结算 Lyra 的结界与 Adagio 的持续治疗和燃烧，两边共用同一份逐 tick 回归用例。[Bevy 实验、完整对局和复现方法](../../tools/bench/bevy-ecs.md)

## 房间初始化

进程启动时用 `WorldRules::load` 编译英雄基础数值、技能、装备和兵线参数。每个新房间共享技能表、商店配方和属性表，单独持有模式商品可用性、装备实例、英雄和计时器。创建不同模式的房间可以并行进行。

在本机实包上执行 `cargo run --release -p halcyon-sim --example room_start_bench -- <delivery> <server_data_extra>`，每轮创建并释放 128 个六人模拟世界，共七轮，交替测两个路径。含规则编译的单房间耗时中位数为 70.426 µs，复用规则为 0.576 µs。每次测量前校验两种入口在同一 seed 的完整初始状态摘要。范围仅含内存中的世界构造与释放，连接、地图开场和 tick 各有单独的测量。
